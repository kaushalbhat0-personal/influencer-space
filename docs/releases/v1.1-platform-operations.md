> **Release Date:** 2026-07-29

## Overview

Platform Operations v1.1 is the second major release of the Creatos Platform. It transforms Super Admin from a basic dashboard into a complete **Platform Operations Center** with operational intelligence, creator and website management, marketplace operations, global activity timeline, and production-ready security hardening.

## Major Capabilities

### Platform Dashboard
- 10 real metric cards (creators, users, agencies, products, gallery, orders, revenue, pro subs, publishes, audit 24h)
- Platform Summary section with architecture health, publishing health, marketplace health, creator growth
- Full tenant ledger with search, actions (login-as, reset password, sync, delete)

### Creator Operations
- Enhanced tenant detail with 7 metric cards
- Activity timeline (last 10 audit log entries)
- Subscription panel with plan, status, users
- Publishing panel with state, version, date
- Health score from WebsiteHealthEngine with improvement suggestions

### Website Operations
- Dedicated `/super-admin/websites` page listing all websites
- Search by creator name, domain, or theme
- Status chip filters (All/Live/Draft/Preview) with counts
- Pagination for large result sets
- Theme name resolved from ThemeRegistry

### Marketplace Operations
- Themes page: 30 themes grouped by 14 categories with color swatches, variants, PRO/Featured badges
- Templates page: 11 templates with pages/sections, status, compatible themes
- Both consume canonical registries exclusively

### Platform Activity
- Real-time operational timeline from audit log
- Grouped by Today, Yesterday, Last 7 Days, Earlier
- Event categorization with icons and colors
- Per-creator deep links
- Sidebar widgets: Recent Publishes, Activity Summary

### Platform Insights
- 7 actionable insight cards: failed publishes, provisioning failures, websites never published, inactive creators, missing domains, platform errors, content summary
- Severity badges (critical/warning/info/success) with color coding
- Action buttons with deep links to relevant pages

### Security
- Auto-login endpoint now requires SUPER_ADMIN session in production
- Dev/seed endpoint now requires SUPER_ADMIN session in production
- All server actions consistently verify SUPER_ADMIN role
- Three-layer defense: middleware (JWT), layout (session), individual checks

## Architecture Summary

- **Architecture frozen:** All core domains are stable and may not be redesigned without ADR
- **One canonical pipeline per operation:** PublishingService, ProvisioningService, WebsiteHealthEngine, CapabilityService
- **Registry-driven:** ThemeRegistry, BlueprintRegistry, MarketplaceRegistry, CapabilityRegistry
- **Snapshot-driven:** Storefront reads only from PublishedSnapshot
- **Builder is layout-only:** No content editing in Builder
- **Marketplace is discovery-only:** No generation, publishing, building, or provisioning

## Upgrade Notes

### From v1.0 to v1.1

No breaking changes. The following files were added:
- 3 new super-admin routes: `/super-admin/activity`, `/super-admin/insights`, `/super-admin/websites`
- 1 new publishing method: `PublishingService.markChangesPending()`

The following changes affect existing behavior:
- `/api/auth/auto-login` now requires SUPER_ADMIN session in production
- `/api/dev/seed` now requires SUPER_ADMIN session in production
- `builder.actions.ts` now uses `PublishingService.markChangesPending()` instead of direct `prisma.publishStatus.update()`
- Sidebar navigation was reorganized into 7 groups (Platform, Creators, Marketplace, Operations, Billing, Audit, System)
