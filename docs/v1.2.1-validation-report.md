## Database Design

### New Model: ClientAssignment

| Field | Type | Constraint |
|-------|------|------------|
| id | UUID | Primary key |
| workspaceId | UUID | FK -> Workspace (CASCADE) |
| tenantId | UUID | FK -> Tenant (CASCADE) |
| userId | UUID | FK -> User (CASCADE) |
| role | String | account_manager, designer, developer, content_editor, support |
| assignedAt | DateTime | Default now() |
| createdAt | DateTime | Default now() |
| updatedAt | DateTime | Auto-updated |

**Unique constraint:** [workspaceId, tenantId, userId]
**Indexes:** workspaceId, 	enantId, userId

### Relations Added
- Workspace.clientAssignments → ClientAssignment[]
- Tenant.clientAssignments → ClientAssignment[]
- User.clientAssignments → ClientAssignment[]

## Migration Strategy

### Legacy Storage (Before)
`
Setting table (key: client_assignments_{agencyId})
  -> JSON blob of assignments array
`

### Canonical Storage (After)
`
ClientAssignment table
  -> One row per assignment
  -> Proper foreign keys and indexes
`

### Fallback Compatibility
1. getAssignments() reads from ClientAssignment table first
2. If empty, reads from legacy Setting JSON
3. If legacy data found, automatically migrates to database
4. Legacy Setting record deleted after successful migration

### Migration SQL
Created at prisma/migrations/20260729_add_client_assignment/migration.sql
