## 5. Authentication Requirements

All credentials are **environment-variable references only** in `opencode.json`
via `{env:VAR}`. No real values were written anywhere in the repo.

| Server | Variable(s) | Required? | Notes |
|---|---|---|---|
| Playwright | — | No | No API key. Headless Chromium reuses the cached Playwright browser install. |
| Context7 | `CONTEXT7_API_KEY` | No (optional) | Works unauthenticated with lower rate limits; add key from context7.com/dashboard for higher limits. |
| Supabase | `SUPABASE_PROJECT_REF` | Yes (before use) | OAuth login also required at first use (`opencode mcp auth supabase`), choosing the org containing the project. Server is hard-scoped `read_only=true`. |
| GitHub | `GITHUB_PERSONAL_ACCESS_TOKEN` | Yes | Fine-grained PAT with read-only scopes; sent as `Authorization: Bearer`. `oauth:false` is set so OpenCode does not attempt the OAuth flow. |
| Grep.app | — | No | No API key. |

**Where to configure locally (Windows):** set the variables as user-level
environment variables (System Properties → Environment Variables, or
`setx VAR value` in a new shell), then restart OpenCode. Do not paste real
values into `.env.example`, `opencode.json`, skills, or docs. `.env*.local`
files are gitignored if the user prefers to keep values in the project dir —
OpenCode does not read them directly; they must still be exported into the
process environment that launches opencode.

## 6. Security Model

- No secrets are printed, echoed, or tested during setup.
- `opencode.json` holds only `{env:VAR}` references.
- `.env.example` holds empty placeholders.
- Supabase defaults to **read-only** (`read_only=true` excludes mutating tools)
  and is scoped to the project ref. No service-role key is used; OAuth is the
  safest available mode.
- GitHub MCP starts with a read-only PAT scope recommendation and a limited
  toolset (`context,repos,issues,pull_requests,actions,code_security`) to
  reduce both blast radius and context usage. Write operations are available to
  the tool but must not be used unless a task explicitly authorizes them.
- No fake credentials were created.

## 16. How Future RCCF Tasks Should Use These MCPs

1. **Browser/route/visual QA** → Playwright MCP, after confirming the dev server
   per `.agents/skills/dev-server-lifecycle/SKILL.md`. Use one canonical
   baseURL. Never use it when static source inspection suffices.
2. **Current third-party docs** (Next.js 14.2, React 18, Prisma 7, Supabase,
   Tailwind, Playwright) → Context7 (`use context7`), including version-specific
   behavior. Never for repository-local code.
3. **Supabase DB/storage/media/QA-data investigation** → Supabase MCP, read-only.
   Never mutate production-like data unless a task explicitly authorizes it.
4. **Issues, PRs, CI, GitHub-hosted context** → GitHub MCP. Use native
   OpenCode git tools for local git operations instead.
5. **Public GitHub implementation research** → Grep.app MCP. Use repository-local
   search when that is sufficient.
6. **General rule:** use the smallest number of tools necessary; do not invoke
   multiple MCPs for the same question without a reason; never expose
   credentials or copy secrets into prompts, reports, screenshots, or skills.
